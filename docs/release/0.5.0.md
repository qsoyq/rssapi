# rssapi 0.5.0

Release boundary: `0.4.13..0.5.0`

## Changes

- Added `/api/rss/instagram/{username}/posts` with pagination and support for image, video, and carousel posts ([#34](https://github.com/qsoyq/rssapi/pull/34)).
- Made the Twitter transaction signer safe to use across concurrent request threads ([#31](https://github.com/qsoyq/rssapi/pull/31)).
- Return explicit HTTP 502/503 responses when the Twitter browser fallback fails ([#32](https://github.com/qsoyq/rssapi/pull/32)).
- Avoid ClientTransaction initialization failures when Twitter omits the ondemand bundle ([#33](https://github.com/qsoyq/rssapi/pull/33)).

No configuration migration is required. The Instagram route adds optional `RSS_INSTAGRAM_*` settings with documented defaults.

## Validation

- `uv run pre-commit run --all-files`: passed, including mypy and the Python 3.10–3.14 tox startup checks.
- `uv run ruff check .`: passed.
- `uv run ruff format --check .`: passed; 135 files were already formatted.
- Deterministic test suite: 171 passed, 28 skipped, and 3 credential-dependent Twitter tests deselected.
- The full local suite was also attempted. Credentialed live integrations encountered external failures: transient GitHub API 504 (the focused retry passed), NGA 504/403 responses, and a Twitter 503 because the local Playwright Chromium executable is not installed. No deterministic test failed; the clean release PR CI remains the merge gate.
- `uv build`: built `dist/rssapi-0.5.0.tar.gz` and `dist/rssapi-0.5.0-py3-none-any.whl`.
- The wheel and sdist report version `0.5.0`, contain all three `rssapi/applications/instagram/` modules, and contain no cache or local-noise files.
- An isolated wheel installation imported the Instagram router, reported package version `0.5.0`, and ran `rssapi-server --help` successfully.

## Known risks

- Instagram relies on an undocumented upstream web API and expiring CDN URLs, so upstream changes may interrupt the feed without notice.
- [Issue #30](https://github.com/qsoyq/rssapi/issues/30) remains open: the production runtime path behind reported Playwright Sync API asyncio-loop errors has not yet been fully diagnosed. This is an accepted, non-blocking risk for 0.5.0.

## Rollback plan

- Before publication: revert the version bump and do not publish `0.5.0`.
- After publication: keep the public `0.5.0` tag and Release immutable, revert or fix the affected change, and publish `0.5.1`.
- If downstream deployment is affected, temporarily point `qsoyq/proxy-tool` back to rssapi `0.4.13` until the corrective release is available.
