# rssapi 0.5.2

Release boundary: `0.5.1..0.5.2`

## Changes

- Instagram post feeds now return a clear authentication error when the upstream service redirects anonymous requests to login, and support passing the verified minimum `ds_user_id` and `sessionid` Cookie fields through either query or request header ([#39](https://github.com/qsoyq/rssapi/pull/39)).
- Cookie values supplied through the query parameter are excluded from the generated feed URL, and authenticated requests bypass the shared anonymous cache.

No configuration migration is required.

## Known risks

- Instagram relies on an undocumented upstream web API and may change its login or response behavior without notice.
- Query parameters remain sensitive in client and server logs; prefer the `X-Instagram-Cookie` request header.

## Rollback plan

- Before publication: revert the version bump and do not publish `0.5.2`.
- After publication: keep the public tag and Release immutable, revert or fix the affected change, and publish a corrective patch release.
