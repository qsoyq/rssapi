# rssapi 0.5.4

Release boundary: `0.5.3..0.5.4`

## Changes

- Add a TikTok user Posts JSON Feed endpoint with a Range-aware media proxy and explicit upstream restriction errors ([#43](https://github.com/qsoyq/rssapi/pull/43)).
- Add a Playwright-backed TikTok v2 endpoint with Cookie Header support, an opt-in loopback-only Cookie Query, bounded browser work, fail-closed private-profile handling, and configurable direct or proxied media ([#44](https://github.com/qsoyq/rssapi/pull/44)).

TikTok v2 returns direct upstream media URLs by default. Set `RSS_TIKTOK_V2_MEDIA_MODE=proxy` to return Referer-aware rssapi media proxy URLs instead. Query Cookie input is disabled by default; enable it only for controlled loopback debugging with `RSS_TIKTOK_COOKIE_QUERY_ENABLED=true`. The runtime must install the Playwright Chromium build that matches the locked Playwright package.

No data migration is required.

## Known risks

- TikTok relies on undocumented web APIs and may return an interactive verification challenge even when Chromium and a proxy are available.
- Cookie Query values may appear in client or server access logs. Query input is disabled by default and must only be enabled in a controlled loopback environment; prefer `X-TikTok-Cookie` elsewhere.
- Direct media is the default, but TikTok returned HTTP 403 without the original post Referer during local validation. Clients that cannot set Referer should use proxy mode.
- Proxy media cold resolution after a process restart or cache expiry requires a configured storage state or a fresh Cookie request.
