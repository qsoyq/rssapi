# rssapi 0.5.6

Release boundary: `0.5.5..0.5.6`

## Changes

- Add a process-local Playwright browser capacity limiter shared by Douyin, TikTok, and Twitter browser paths. Configure the limit with `RSS_PLAYWRIGHT_CONCURRENCY` (default `11`).
- Add TikTok v2 browser phase diagnostics, short queue rejection, and transient failure-cache bypass so overloaded requests return a retryable `503` instead of occupying the full browser timeout.
- Ensure shared asynchronous Playwright setup closes already-created browser resources when setup fails.

No data migration is required.

## Validation

- `uv lock --check`: passed.
- `uv run ruff check .`: passed.
- `uv run ruff format --check .`: passed.
- `uv run pytest tests/`: 251 passed, 25 skipped.
- `uv build`: built `rssapi-0.5.6` wheel and source distribution.

## Known risks

- The global capacity limit is process-local. Multi-worker deployments must divide the available browser budget across workers.
- TikTok still depends on undocumented upstream browser APIs and may return an interactive verification challenge.

## Rollback plan

- Before publication: revert the version bump and do not publish `0.5.6`.
- After publication: keep the public release immutable, revert the runtime change, and publish a corrective patch release.
