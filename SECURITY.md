# Security Policy

## Reporting a vulnerability

Please report suspected vulnerabilities privately instead of opening a public Issue.

For this personal repository, contact the maintainer through the GitHub profile for `@qsoyq` or by opening a minimal public Issue that asks for a private contact channel without disclosing exploit details.

## What to include

- Affected route, module, or dependency.
- Impact and likely severity.
- Reproduction steps or proof of concept, if safe to share privately.
- Whether any credentials, tokens, cookies, or user data may be affected.

## Handling expectations

- Do not publish secret values, private keys, cookies, tokens, or production configuration.
- If a credential is exposed, revoke and rotate it before documenting the incident.
- Security fixes should go through PR review and CI unless immediate containment is required.
